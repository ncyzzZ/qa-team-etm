# SIMOP / Shutdown Logic conflict-check rules (learned on ETM-7289, Oct 2026)

Confirmed by the user, not all written in the AC. Do not raise them again as BA questions.

- **Matrix source**: Excel `Activities SIMOP Matrix_Rev.1.xlsx`, visible sheet `SIMOP Table` (rows 3-22): 20 activities coded A-U (no R), lower-triangle and symmetric (same cell whichever is X or Y), diagonal (same activity twice) is blank. An older file had two tables on one sheet with 38 differing cells. Always ask the user for the current file before quoting any cell, and say which file version was used.
- **Value to colour**: `P` Prohibit = red, `R` Restriction = yellow, `A` Allow = green. A task takes the strongest colour among everything it conflicts with (green, yellow, red): red if any P, yellow if any R and no P, otherwise green.
- **Where a task's activity comes from**: the **Work Conflicted** multi-select in the Breakdown Setting window (open it with the list icon in the task's Predecessor column). A task with no Work Conflicted value is not checked. A task with two activities takes the strongest result of all of them.
- **What counts as a conflict pair** (all must be true): same **platform** (top-level rows such as ASSET or BS; different platforms never conflict); times overlap (end = start, touching bars, is NOT an overlap); and Working Location **Deck, X and Y each share at least one value**. No overlap means no conflict and the bar stays green.
- **What changes colour**: only lowest-level tasks (no expand arrow, no children). Parent/group rows never change colour.
- **Edit SIMOP window**: right-click the task bar, then **Edit SIMOP** (the menu also has Edit Breakdown). Columns: Description / Activities SIMOP Matrix (Prohibit, Restriction, Allow) / Override Conflict (Allow or Prohibit) / SIMOP Status. The user's Override Conflict always wins over the matrix value.
- **SIMOP button**: test as Turnaround Manager only (Bkk41), no permission/role cases. The user chose not to test the loading/spinner state; the button is otherwise always enabled, including when Save is disabled and when there are unsaved edits. SIMOP must not run on page load (GET Gantt) or on Save; Save becomes enabled only if a colour changed; SIMOP clears Undo/Redo and cannot be undone (button or Ctrl+Z); colours are kept only after the global Save; leaving after a colour change shows the Cancel / Discard warning.
- **API error case**: write one NEG TC. Set DevTools Network throttling to Offline, click SIMOP: a fail toast shows, colours and Save stay unchanged, button usable again; back online it works. The Validation&Result sheet (Confirmation&Result, row 13 "API Error Occurred") is for the **Optimizer**, not SIMOP, so write only "a fail toast shows" and do not copy the Optimizer wording.
- **Same-activity pair** (matrix diagonal blank): skip, no TC and no BA note (user decision).
- **TC set size**: keep it small (the user cut 32 TCs to 19 on ETM-7289). Merge similar cases into one TC with several rounds: one TC per colour (red / yellow / green, two pairs each, the red one also swaps the two activities), one strongest-colour TC with three tasks, one two-activity TC, NEG TCs for different platform / location (Deck, then X, then Y rounds in one TC) / time (no overlap, then touching) / no Work Conflicted, parent rows, override (Allow then Prohibit), Save button, Undo/Redo + Ctrl+Z, kept-only-after-Save, leave-page warning, page-load + Save do not run SIMOP, click runs it once, API error. Leave an "every matrix cell" loop to Playwright rather than writing every cell manually. Descriptions cite the Figma link and ETM-2614 / ETM-6919 but no AC numbers.
- **QA test data** (plan URL, task rows, Deck/X/Y options): not stored in this skill. Read `docs/etm-7289-status.md`, section "QA test data", only when picking tasks. If that doc is not available to you, ask the user for the plan URL and task rows instead of guessing. Rules that always apply: use a different Deck per TC within a platform; steps say "Set ... to only <value>"; put the chosen rows and Deck/X/Y in the **Data** column of the "pick tasks" step.
- **Xray push notes**: `createTest` needs `jira.fields.project: {key: "ETM"}`; one GraphQL document may hold at most 25 operations (split bigger batches); `updateTestStep` accepts partial fields (e.g. only `data`). If Playwright cannot install its browser on the user's machine, ask the user for screenshots instead of opening Chrome.
