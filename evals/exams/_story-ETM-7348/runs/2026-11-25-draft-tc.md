# Draft test cases: ETM-7348 Shutdown Timeline - Edit Plan Screen & Task Planning Specifications

Story: ETM-7348 (exam copy, frozen 2026-11-11). Source: `story.md` (description + 2 BA comments 5 Nov and 9 Nov), `docs/modules/shutdown-timeline*.md`, `knowledge/`. No analyst.md and no inspector.md: AC ids below are numbered by the Story's own numbering (AC-1.1 = AC 1 item 1, and so on); AC-n.x ids are used in `Trace:`.
Existing `[QA]` subtasks: not read (no Jira access in this run).
Priority: the Story has none, so priority is set by damage if it breaks (stated here once).

Common precondition ("common"): QA environment, a Shutdown Event with a seeded Timeline plan (several Activity Groups, each with activities), logged in as a Turnaround Manager who has View Timeline and Edit Plan, on the `Timeline` tab. Cases that start on the Edit Plan screen say so.
Notation: `->` separates action and expected result. Text in backticks is the exact on-screen text. Dates are `DD Mmm YYYY`, time zone UTC+7 (Asia/Bangkok).
Think-like-the-user notes: a Turnaround Manager edits the baseline plan a few times per event, usually before the shutdown, often with a long list of rows; wants to add/reorder/delete quickly and see that the total is 100.0; a rushed user presses Save twice, leaves with the side menu, deletes a row by mistake (no confirm), edits while a colleague updates progress on Timeline in another tab.

## Open questions (return to lead)

1. Conflict modal title: BA comment 5 Nov says `Plan has Been Changed`, the description and comment 9 Nov say `Progress has been updated`. TC-048 uses the description text. Confirm.
2. Edit Activity Group: is `[ Save ]` disabled when the name is cleared (the Story says it only for Add)? TC-022 assumes it is, because the name is mandatory.
3. Field table says Group Activity default `New Activity Group`, but the Add Activity Group modal has an empty input with placeholder. Which text does a new group get when the name is typed? TC-017 assumes the typed name.
4. Plan (%) typed above 100.0 (for example `100.1`) or below 0.0: is it refused, capped, or shown red? Story gives only range [0.0, 100.0]. TC-034 expects the value is not kept above 100.0 and asks the tester to note what happens.
5. Plan (%) with more than 1 decimal (`12.34`): rounded or cut? And non-numeric text?
6. Does a drag reorder alone make the screen dirty (enable `[ Save ]`, trigger Unsaved Change)? TC-029 assumes yes because the order is saved.
7. Exact text of the red tooltip on `Total Progress` -> `Plan (%)` is not in the Story (only the red colour and disabled Save).
8. User without Edit Plan opens the screen URL directly: what is shown (`Not found`, redirect, message)? TC-003 expects only that the screen and its data are not shown.
9. Date rules versus Ramp down / Ramp up dates: can a date outside the ramp range be picked? Not in the Story.
10. Weekly cells: the Story says read-only (AC 3.2). The module notes say a later Story (ETM-8405) makes weekly Plan (%) editable. TC-010 follows this Story.
11. Duplicate Activity Group names and case variants: allowed? Not in the Story.
12. `Minor SD` Optional tasks: are they listed with empty Start/End (red) or omitted? Needs a QA plan with Minor SD.
13. Does `Delete Activity Group` (no confirm) also mark the screen dirty and does `Back` + `Discard Change` bring it back? Assumed yes (TC-024).
14. After Save fails (`Save Failed`), does the user stay on Edit Plan with edits kept and Save enabled? Assumed yes.
15. Where is the `Shutdown Size` control's behaviour (override, recalculation)? Belongs to ETM-7984; only presence is tested here.
16. Suggestion (not in Story): keyboard-only use, browser zoom, session expiry in Edit Plan. Not written.
17. Suggestion (not in Story): a leave-page prompt on browser refresh/close. Story only names `[ Back ]` and the side menu.
