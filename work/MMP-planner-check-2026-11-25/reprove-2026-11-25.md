## P15 Chart range vs schedule range: proved (the chart and table are wrong)

Steps (TM, plan B):
1. Open plan B and read the schedule header (`.mob-plan__day-head`) at scroll left 0 and at the right end. The grid is virtualized: scrollWidth 1728 = 27 x 64 px.
2. Read the POB chart data table header (AG Grid).
3. Read the API responses the page loads: `.../manpower-mob/chart` and `.../manpower-mob/period`.
4. Open plan B Shutdown Logic (`.../planning/812889f6.../logics/e8d06cc8-964d-47b1-bbf4-7649ac89dc33`) and hide the histogram (`Hide histogram` in `sl-splitter-horizontal`).
5. Read the task start and end dates from the Bryntum Gantt task store.

Measured facts:
- **Schedule grid: 14 May 2026 to 9 Jun 2026** (27 days; first header `May 2026 / 14`, last `Jun 2026 / 9`).
- **Data table: 12 May to 30 May 2026** (19 columns x 60 px = 1140 px).
- **Chart X axis: 12 May to 30 May.**
  - The canvas is 1140 px wide, the same as the table, and its labels read 12 May ... 30 May in the pictures.
  - The `chart` API returns `startDate 2026-05-12`, `endDate 2026-05-30` and 19 values.
  - No Chart.js instance is exposed on the page, so the axis was read from the picture and the API.
- **Tasks (Shutdown Logic, eND50): Earliest Task Start Thu 21 May 2026 08:00; Latest Task End Tue 2 Jun 2026 11:00.** These match the plan's ramp-down 21 May 08:00 and ramp-up 2 Jun.
- Expected range = 21 May - 7 to 2 Jun + 7, which is **14 May to 9 Jun**. The schedule grid matches; the chart and table do not.
- Likely cause: the chart uses the `manpower-mob/period` range (startDate 19 May, endDate 23 May, the Required Manpower period dates) +/- 7 days, which gives 12-30 May. This is a guess from the numbers, not from the source.

ETM-6378 AC 3.3.1 asks for a chart from Earliest Task Start - 7 to Latest Task End + 7.

## P16 Chart/table alignment: proved (minor)

Steps (TM, plan B):
1. Scroll the POB chart into view.
2. Measure at the left end.
3. Scroll the table fully right with a horizontal mouse wheel over the table (the chart follows) and measure.
4. Scroll back fully left and measure again.
5. Read the canvas pixels (`getImageData`, dpr 1) to find where the line's points sit.

Measured facts:

| | Left end | Right end |
|---|---|---|
| Table scrollLeft | 0 | 186 (max) |
| Chart scroller scrollLeft | 2 | 188 (its max would be 204) |
| Canvas left vs table column 12 left | 0 px (293 vs 293) | 0 px (107 vs 107) |
| Canvas right vs table column 30 right | | 0 px (1247 vs 1247) |

So the canvas element itself is aligned at both ends.

The two viewports differ:
- The chart scroller box is x 295-1231 (936 px). The table viewport is x 293-1247 (954 px).
- The 2 px on the left is cancelled by the 2 px extra scroll, so the content still lines up.
- On the right, the chart cuts off 16 px that the table shows. The "30 May" label is cut in the right-end picture.
- The table body shows no vertical scrollbar, so these 16 px do not look like a scrollbar.

Point positions inside the canvas, against the table column centres (30 + 60 x i):

| Point | Drawn at x | Table column centre | Offset |
|---|---|---|---|
| First point, 12 May | 37 | 30 | +7 px |
| 21 May (line starts rising) | 574 | 570 | +4 px |
| 25 May (back to 0) | 810 | 810 | 0 px |
| Last point, 30 May | 1109 | 1110 | -1 px |

- The drawn spacing is about 59.6 px, not 60. The chart area seems to have about 7 px of left padding.
- So each point sits inside its column, but not exactly at the centre: up to 7 px off at the left end and about 0 px at the right end.
- This is measured from the line pixels, not from the Chart.js scales (not reachable).
- The 2 px gap the planner saw is only the chart scroller offset (2 px). With the box offset, the canvas still lines up.

ETM-6378 AC 2.5 asks for "strictly aligned". Severity is minor.
