4. AI team ทำอะไรได้บ้าง4. What the AI team can do

  • automation-engineer: คัด TC ที่ทำ Playwright ได้ เขียน spec, security check และคำสั่งรันAutomation Engineer for the ETM QA team. Use after the tests are in Xray, to sort which Tests can be Playwright scripts and to write the specs, the security checks and the run command
  • ba-analyst: อ่าน Story, AC และ [QA] subtask ก่อนทุกการ์ด แล้วลิสต์จุดที่ไม่ชัดให้ BABA Analyst for the ETM QA team. Use first on every ETM Story, to read the Story, its acceptance criteria and QA subtasks and list what is unclear
  • evidence-reporter: สร้าง evidence report HTML จากผลรัน และสรุปผลสั้น ๆEvidence Reporter for the ETM QA team. Use after the user says a Playwright run is done, to build the HTML evidence report, and for short summaries of results.
  • jira-xray-logger: push test ขึ้น Xray, ตั้ง Test Plan / Execution, log defect และปิดงาน หลังคนอนุมัติเท่านั้นJira and Xray hands of the ETM QA team. Use only after the user's explicit go-ahead, to push tests to Xray, set up the Test Plan and Test Execution, log defects and retests, and do the closeout.
  • playwright-healer: เปิดหน้าจริงหา locator ใหม่เมื่อหาจากโค้ด FE ไม่เจอ เสนอเท่านั้น ไม่แก้ไฟล์เองLive step of self-healing for the ETM QA team. Use only when the FE-source lookup (tools/heal/source-lookup.mjs) found no replacement for a broken locator, the locator is a library class (Bryntum b-*, AG Grid ag-*), or a source heal failed its re-run
  • test-designer: ออกแบบและเขียน test case ทั้ง manual และพร้อมทำ automation จาก Story และข้อที่พบSenior Test Designer for the ETM QA team (merged with the senior-test-designer skill). Use to design and write test cases, manual and automation-ready, from the Story, the analyst notes and the design findings
  • test-reviewer: ตรวจ draft TC ว่าครอบคลุมและชัด ส่งกลับถ้ายังไม่ดีพอTest Reviewer for the ETM QA team. Use after the test designer wrote a draft, to check coverage and wording and send it back when it is not good enough
  • ux-inspector: อ่าน Figma ทุกสถานะของหน้าจอ หาจุดที่ design กับ AC ไม่ตรงกันUX/UI Inspector for the ETM QA team. Use when an ETM Story has screens
  • Quality gates (tools/qa-check.mjs): ตรวจ draft TC, spec, coverage, AC strength, state.json ทุก phase · กัน test ที่ขึ้นเขียวโดยไม่ได้ตรวจ (false pass) · push ขึ้น Xray เฉพาะผลที่ผ่านในการรันจริงพร้อมรูปทุก stepchecks the draft TC, spec, coverage, AC strength and state.json at every phase · blocks tests that turn green without checking (false pass) · pushes to Xray only results that passed in a real run, with a picture for every step
  • Self-healing (tools/heal/): อ่านโค้ด FE ของ dev หา locator ที่เปลี่ยน ก่อนรันและหลัง fail · คนอนุมัติทุกครั้งก่อนแก้reads the developers' FE code to find changed locators, before a run and after a failure · a person approves every fix
  • Evidence report (tools/run-card.mjs): สร้าง report พร้อมรูปทุก step อัตโนมัติหลังรัน · แยกสาเหตุ fail (locator / data / env / assertion / flaky)builds the report with a picture of every step after each run · sorts each failure by cause (locator / data / env / assertion / flaky)
  • Human in the loop: ทุกการเขียนลง Jira / Xray / ข้อมูล QA ต้องมีคนอนุมัติบน board หรือในแชท และบันทึกไว้ใน state.jsonevery write to Jira / Xray / QA data needs a person's approval on the board or in the chat, recorded in state.json

วิธีอ่านHow to read
  • Defect = issue type Defect (เจอใน QA) · Bug = issue type Bug (หลุดไป UAT/PROD) · นับตาม Sprint ของ defect เอง หารด้วยจำนวน Story ใน sprint นั้น (Story ที่ยกข้าม sprint นับทุก sprint)Defect = issue type Defect (found in QA) · Bug = issue type Bug (escaped to UAT/PROD) · counted by the defect's own sprint, divided by the Stories of that sprint (a carried-over Story counts in every sprint)
  • กันได้ = BA แก้/เพิ่ม AC หรือ dev แก้ก่อนส่ง QA เพราะข้อที่ทีมยก · ยืนยันเดิม = BA ยืนยันพฤติกรรมเดิม ไม่นับว่ากันได้Stopped = BA changed/added AC or dev fixed before QA because of a point the team raised · Confirmed as is = BA kept the behaviour, not counted as stopped
  • ก่อน / หลัง dev = สถานะ Story ตอนที่ยกข้อนั้น · เตือนแล้วยังเกิด = defect ที่ทีมเคยเตือนไว้แต่ไม่ได้แก้Before / after dev = the Story status when the point was raised · Warned, still happened = a defect the team had warned about that was not fixed
  • เติมย้อนหลัง = ข้อของการ์ดที่บันทึกหลังเหตุการณ์ (Sprint 26)Backfilled = points recorded after the fact (Sprint 26)
  • * = sprint ที่ยังไม่จบ ตัวเลข defect ยังไม่ครบ ห้ามเทียบกับ sprint ที่จบแล้ว* = sprint not finished: defect numbers are incomplete, do not compare with finished sprints
  • สิ่งที่ตัวเลขนี้ไม่ได้พิสูจน์: ความยากและขนาดงานแต่ละ sprint ต่างกัน · การเทสที่ดีขึ้นอาจทำให้ Defect ใน QA เพิ่มขึ้นในขณะที่ Bug ที่หลุดลดลง จึงแสดงทั้งสองเส้น · "-" คือไม่มีข้อมูล ไม่ใช่ศูนย์What these numbers do not prove: sprints differ in size and difficulty · better testing can raise QA defects while escaped bugs fall, so both lines are shown · "-" means no data, not zero
