# ETM-8042 [Improvement] Planning - Individual Ramp Down & Up Date
Status: Open
Subtasks: ETM-8538 [FE] Update UI [Open], ETM-8539 [FE] Unit test [Open], ETM-8540 [BE] Improve API [Open], ETM-8541 [BE] Unit test [Open]
Links: Relates ETM-8040

## Description
**As a** Turnaround Manager  
**I want to** set a Ramp Down Date and Ramp Up Date for each Plan  
**So that** I can prepare several plan scenarios with different shutdown windows, and every page under the Plan uses that Plan's own dates.

Ref: [ETM-4141](https://pttep.atlassian.net/browse/ETM-4141), [ETM-4530](https://pttep.atlassian.net/browse/ETM-4530), [ETM-4144](https://pttep.atlassian.net/browse/ETM-4144), [ETM-5386](https://pttep.atlassian.net/browse/ETM-5386)

---

**Pre-Conditions**

* The user is logged into the STMS application and possesses the **Create Plan** or **Edit Plan** permission in [Role & Permission](https://pttep.sharepoint.com/:x:/r/sites/TurnaroundManagement/Shared%20Documents/03%20Development/Role%20%26%20Permission%20V.2.xlsx?d=wa5e5a9a2071b4ed7b3ef83c4cf0dffd9&csf=1&web=1&e=3stFwC).
* The user is on the **Planning** tab of a Shutdown Event.

---

**Data Source**

* **Shutdown Event**: Planned Date (Start Date Time / End Date Time) — used as the default value only.
* **Plan (new fields)**: Ramp Down Date (date and time), Ramp Up Date (date and time).
* **Daily Report (new fields)**: snapshot of the Plan's Ramp Down Date and Ramp Up Date, taken when the Daily Report is created.

---

**Acceptance Criteria**

1. **Ramp Down/Up Date field in Create Plan modal**:

    1. The **Create Plan** modal has a new mandatory field **Ramp Down/Up Date**, placed between **Plan Name** and **Description**.
    2. The field is a date-time range picker (Start = Ramp Down, End = Ramp Up). Values display as `DD Mmm YYYY HH:mm` (e.g. `08 Feb 2025 08:00`). Picker interaction is aligned with the Planned Date picker in [ETM-1701](https://pttep.atlassian.net/browse/ETM-1701).
    3. The field is pre-filled with the Shutdown Event's **Planned Date** (Start → Ramp Down, End → Ramp Up). The user can change it.
    
2. **Ramp Down/Up Date field in Edit Plan modal**:

    1. The **Edit Plan** modal shows the same field, pre-populated with the Plan's current Ramp Down/Up Date.
    2. The dates can be edited at any time. They are not affected by the Worklist status (e.g. `Freeze`).
    
3. **Validation**:

    1. **Ramp Up Date** must be the same as or later than **Ramp Down Date** (equal is allowed).
    2. The dates do **not** need to be within the Shutdown Event's Planned Date.
    3. Save behavior, success/fail toasts and other field validations follow the existing Create Plan / Edit Plan behavior ([Planning Validation&Result.xlsx](https://pttep.sharepoint.com/:x:/r/sites/TurnaroundManagement/Shared%20Documents/03%20Development/Form%20Validation%20%26%20Result/Planning%20Validation%26Result.xlsx?d=wb9f268567da14f23ae29505c9571d22c&csf=1&web=1&e=2gdvhc) › Confirmation&Result R3–R8).
    
4. **Plan Card Display**: The Plan Card header shows a badge next to the Plan Name: `Ramp Down/Up Date: DD Mmm YYYY HH:mm - DD Mmm YYYY HH:mm`.
5. **Independence from the Shutdown Event**:

    1. Each Plan has its own Ramp Down/Up Date.
    2. After a Plan is created, changing the Shutdown Event's Planned Date does **not** change the Plan's Ramp Down/Up Date.
    
6. **Existing Plans (data migration)**: For every Plan that exists before this release, Ramp Down/Up Date is set to the Shutdown Event's Planned Date.
7. **Duplicate Plan**: Duplicating a Plan copies the source Plan's Ramp Down/Up Date to the new Plan (Aligned with [ETM-5386](https://pttep.atlassian.net/browse/ETM-5386)).
8. **Pages that use the Plan's Ramp Down/Up Date instead of the Shutdown Event's Planned Date**:

    1. **Shutdown Logic**:
    
        * The `Ramp Down` / `Ramp Up` vertical lines and header badges ([ETM-7897](https://pttep.atlassian.net/browse/ETM-7897)) are drawn at the Plan's Ramp Down / Ramp Up Date.
        * When a Shutdown Logic is created, the schedule Start Date ([ETM-11](https://pttep.atlassian.net/browse/ETM-11) AC 3.1) is set from the Plan's Ramp Down Date.
        * Changing Ramp Down/Up Date later only moves the vertical lines. Tasks are not rescheduled.
        * Export Excel ([ETM-6538](https://pttep.atlassian.net/browse/ETM-6538)): the metadata `Start Event Date` / `End Event Date` are replaced by `Ramp Down Date` / `Ramp Up Date` with the Plan's values.
        * Export file Day numbering ([ETM-5492](https://pttep.atlassian.net/browse/ETM-5492)): `Day1` = the Plan's Ramp Down Date.
        * Export PDF timeframe ([ETM-7900](https://pttep.atlassian.net/browse/ETM-7900)): the Full Shutdown Timeframe and the Day-1 rule use the Plan's Ramp Down / Ramp Up Date.
        * **Optimization** ([ETM-92](https://pttep.atlassian.net/browse/ETM-92)): the start and end dates sent to the Optimization Module use the Plan's Ramp Down Date and Ramp Up Date, instead of the Shutdown Event's Planned Date.
        * **Optimization Feedback Panel** ([ETM-6373](https://pttep.atlassian.net/browse/ETM-6373) AC 3.3): the Event dates in the **Summary** section show the Plan's Ramp Down / Ramp Up Date.
        
    2. **Daily Report**:
    
        * When a Daily Report is created, it stores a snapshot of the Plan's Ramp Down Date and Ramp Up Date. Editing the Plan's Ramp Down/Up Date later does **not** affect that Daily Report.
        * The First Execution Date ([ETM-4120](https://pttep.atlassian.net/browse/ETM-4120) AC 3) is calculated from the snapshot Ramp Down Date and time (before 18:00 → Ramp Down Date - 1; at or after 18:00 → Ramp Down Date).
        * The Gantt chart scale ([ETM-4122](https://pttep.atlassian.net/browse/ETM-4122) AC 1) is based on the duration between the snapshot Ramp Down Date and Ramp Up Date, instead of the Shutdown Event's duration. The scale rule itself is unchanged.
        * The last execution day ([ETM-4125](https://pttep.atlassian.net/browse/ETM-4125) AC 8) and the end of the Planned S-Curve ([ETM-4127](https://pttep.atlassian.net/browse/ETM-4127) AC 3) use the snapshot Ramp Up Date.
        * **Last Execution Day Extension** ([ETM-4125](https://pttep.atlassian.net/browse/ETM-4125) AC 8): when the user freezes the last execution day with tasks below 100% and chooses to extend, the extension moves the **Plan's Ramp Up Date** (instead of the Shutdown Event's End Date) and the Daily Report's snapshot Ramp Up Date together. The Shutdown Event's Planned Date is not changed.
        * Export PDF Day numbering ([ETM-5277](https://pttep.atlassian.net/browse/ETM-5277)) and timeframe ([ETM-7901](https://pttep.atlassian.net/browse/ETM-7901)) use the Daily Report's snapshot Ramp Down / Ramp Up Date.
        * The Ramp Down / Ramp Up vertical lines are covered in [ETM-8392](https://pttep.atlassian.net/browse/ETM-8392).
        
    3. **Manpower Mob Plan**:
    
        * When a date field is blank, its date picker opens on the month of the Plan's Ramp Down Date ([ETM-5616](https://pttep.atlassian.net/browse/ETM-5616)).
        * Export Excel ([ETM-6396](https://pttep.atlassian.net/browse/ETM-6396)): `Start Event Date` / `End Event Date` are replaced by `Ramp Down Date` / `Ramp Up Date`.
        
    4. **Equipment Mob Plan**:
    
        * When a date field is blank, its date picker opens on the month of the Plan's Ramp Down Date ([ETM-7311](https://pttep.atlassian.net/browse/ETM-7311)).
        * Export Excel ([ETM-7315](https://pttep.atlassian.net/browse/ETM-7315)): `Start Event Date` / `End Event Date` are replaced by `Ramp Down Date` / `Ramp Up Date`.
        
    
9. **Pages not changed**: The **Shutdown Timeline** tab (header Ramp down/up date and the Ramp Down anchor when the Shutdown Size changes, [ETM-7984](https://pttep.atlassian.net/browse/ETM-7984)) keeps using the Shutdown Event's Planned Date.
