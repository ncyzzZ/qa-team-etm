## Problems

**TC vs AC or BA**
- **ETM-8681.** Xray still reads "a user without any Daily Report view permission cannot see the table". In ETM only TM and JO exist, so that user does not exist. The draft (TC-003) and the script test something else: a Job Owner on a Plan that is not Active (PERM:45-69). Update the Xray summary and steps (handover item 4), or the Xray result will not match its TC. ETM-8678's Xray text is also the old version.
- **ETM-8724 (AC 1.6)** cannot be executed on QA (no empty value possible). Either ask the BA or Dev whether an empty Plan/Actual can occur at all, or mark the Test as not applicable. Do not leave it TO DO forever.

  - Q1 → 8725.
  - Q2 → 8724.
  - Q3a green background at 100% → 8702 step 6.
  - Q3c Total row → 8726.

  No question is open.

**Scripts**
- **8681 can pass without proof.**
  - When the DB cannot say whether the plan is inactive (`inactive === null`), the test only adds a `partial` note and goes on (PERM:51). A PASSED result could then be for an Active plan.
  - Step 2 checks only that no link named exactly "Daily Report" exists (PERM:60). That is true for every user, because the report is reached from the planning list, so the step proves nothing.
- **8699 steps 4-5 and 8700 steps 1, 6** call `verifyRow` without increasing `run.checked` (MAIN:329, :335, :349, :383). They still assert, so they are not false passes; only the count is off.
- **Stale header comment:** MAIN:13 says 8678 is manual, but PERM:17 scripts it.
- **8691 fallback.** When the exact Plan value is missing, the script tests a different pair "on the same side" (MAIN:175-181). It is marked `notChecked`, so the test ends skipped. Correct, but on QA data most pairs (100/99, 0/1, 1/0) will likely fall back, so 8691 rarely gets a real PASS.
- `classify()` in actualColorPage.ts:89-96 uses thresholds, not exact hex. The AC gives no hex values, so this is acceptable.

**Not scripted:** 8702 and 8726 (PDF, manual).
