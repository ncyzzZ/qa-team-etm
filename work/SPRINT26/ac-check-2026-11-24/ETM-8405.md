## Problems
1. **AC 2.2 contradiction (ETM-8640 steps 6 and 17).** The TC expects "group row shows no Plan (%) summary". The AC says "The Activity Group summary ... must update accordingly". The rule comes from a user decision (18 Nov), not from BA, and the AC text has not changed. The script asserts `groupSummaryValue(GROUP)` is `null` (`verifyWeeklyPlanEdit.spec.ts:168`, `:196`). Ask BA to remove the clause from the AC, or test the summary.
2. **R3-1 not settled.** `findings.json` F-8 says it was "answered (user said)", but ETM-8643 steps 18 and 21 are still marked "user decision, not yet confirmed by BA" (blank Plan week with Actual > 0 shows a Red/Green bar). No BA reply for it is recorded in the module doc or in Jira comments.
3. **Xray ETM-8645 and the script use different Actual data.**
   - The Xray steps expect Actual values `7.5` / `15.5`, which give Plan `43.0`, then `27.5`, then `7.5` (steps 13-15, 18, 20).
   - The script uses the card-data Actual values `5.0` / `10.0` (`spec.ts:410-421`, `:415`; helpers `ACTUAL_SAVED`), which give `35.0`.
   - The script's comment says it knows this ("Xray TC-008 said 7.5 / 15.5"). The Xray steps were never updated, so the evidence does not match the Xray step text.
4. **3 TCs have no script (8643, 8644, 8646).**
   - These cover AC 4.2 (Save, Main Timeline, bars), AC 5 (Shutdown Size) and the Save-failure toast.
   - All three are Closed in Jira since 20 Nov, but there is no automated evidence for them in `run-results.json`.
   - The typed-edit Unsaved Change flow (AC 4.1) also exists only in 8643.
5. **A step can pass without checking.** `skipNoSeed` (`spec.ts:18-21`) turns a missing seed into a passing step with a `skipped-step` note:
   - ETM-8638 step 9, at `:63`;
   - ETM-8645 steps 13-15, at `:406`, `:413` and `:420`.
   - This did not happen on 20 Nov (0 skipped), but a run without the card data reset would show green.
6. **Minor.**
   - The spec header still says "NOT RUN against the app yet" (`spec.ts:15`).
   - The security spec S1-S3 are `test.skip` (`security.spec.ts:17-37`).
   - The security spec S4 accepts `0.0` for a cleared cell as a workaround for defect ETM-8671 (`security.spec.ts:56`). ETM-8671 and ETM-8672 are now Ready for UAT, so tighten it to blank only.
   - 8642 (`spec.ts:257-266`) passes as long as the engine output differs from the manual values; it does not prove pro-rata.
