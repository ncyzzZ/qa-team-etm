# ETM-8405 [Improvement] Shutdown Timeline - Editable Weekly Plan (%) in Edit Plan
Status: Open
Subtasks: ETM-8408 [FE] update logic calculate progress plan %  [In Progress], ETM-8522 [QA] Create Test Case Manual Test [Open], ETM-8523 [QA] Execute Test Case Manual Test [Open]

## Description
**As a** Turnaround Manager  
**I want to** edit the weekly Plan (%) of an activity directly in the Edit Plan screen  
**So that** I can shape the planned progress of each week to match the real preparation schedule, instead of being limited to the automatic even distribution.

Ref: [ETM-7348](https://pttep.atlassian.net/browse/ETM-7348) · [ETM-7346](https://pttep.atlassian.net/browse/ETM-7346)

**Acceptance Criteria**

1. **Editable Weekly Plan (%) Cells** (replaces "Weekly Timeframe Cells … read-only" in [ETM-7348](https://pttep.atlassian.net/browse/ETM-7348) AC 3.2):

    1. In the Edit Plan screen, the weekly Plan (%) cells of an activity are editable **only for weeks within the activity's Start Date – End Date range** (the cells that already show a planned value, including weeks showing `0.0`).
    2. Weekly cells outside the activity's date range remain read-only and empty. The user cannot add planned progress to a week outside the date range.
    3. If an activity has no Start Date or End Date, all its weekly cells remain read-only and empty. (Aligned with [ETM-7346](https://pttep.atlassian.net/browse/ETM-7346) AC 3.4)
    4. Weekly `Actual (%)` cells remain read-only in Edit Plan. (Aligned with [ETM-7348](https://pttep.atlassian.net/browse/ETM-7348) AC 3.2)
    5. **Input Rules** (Aligned with [ETM-7349](https://pttep.atlassian.net/browse/ETM-7349) AC 2.4):
    
        * `0.0` is a valid value.
        * **Typing Keystroke Blocking**: Typing more than 1 decimal digit is blocked.
        * **Pasted Value Truncation**: If a value with more than 1 decimal place is pasted into a cell, the system keeps only the first decimal digit and cuts off the rest; it does **not** round (e.g., pasting `12.36` becomes `12.3`, `12.34` becomes `12.3`).
        * **Upper Clamping**: A value greater than `100.0` typed or pasted into a weekly cell is set to exactly `100.0`.
        * Clearing the cell or entering negative/invalid input leaves the cell **blank**, even when the week is within the date range. A blank week is counted as `0.0` when summing the activity's `Plan (%)` (AC 2.1).
        * Paste into weekly Plan (%) cells is also supported; detailed copy & paste behavior is defined in [ETM-8388](https://pttep.atlassian.net/browse/ETM-8388).
        
    
2. **Recalculate Plan (%) from Weekly Values**:

    1. When the user edits a weekly Plan (%) cell, the activity's `Plan (%)` must be recalculated as the **sum of its weekly Plan (%)** values.
    
        * Blank weeks count as `0.0`. If every week of the activity is blank, its `Plan (%)` shows `0.0`.
        
    2. The Activity Group summary and the `Total Progress` → `Plan (%)` must update accordingly.
    3. If the new `Total Progress` → `Plan (%)` is not `100.0`, the existing blocking error applies: red cell background (`#FFCCC7`) and `[ Save ]` disabled. (Aligned with [ETM-7348](https://pttep.atlassian.net/browse/ETM-7348) AC 4.4)
    4. **No Upper Limit on Calculated Activity Plan (%)**: The activity's `Plan (%)` calculated from the sum of its weekly values is **not** clamped. It is stored and displayed as calculated, even when it is greater than `100.0` (e.g. weekly values `60.0` + `70.0` give `Plan (%) = 130.0`). This replaces the `max 100.0` in [ETM-7348](https://pttep.atlassian.net/browse/ETM-7348) AC 3.1 for calculated values only.
    
        * The activity row and the Activity Group summary do not show an error for a value above `100.0`. Only `Total Progress` → `Plan (%)` shows the blocking error (AC 2.3).
        
    
3. **Rewrite Weekly Values from Start Date, End Date or Plan (%)**:

    1. When the user edits the activity's `Start Date`, `End Date` or `Plan (%)`, the system must recalculate **all** weekly Plan (%) values of that activity using the Day-Weighted Cumulative Pro-Rata distribution engine, **overwriting** any weekly values the user edited before. (Aligned with [ETM-7346](https://pttep.atlassian.net/browse/ETM-7346) AC 3)
    2. The overwrite happens immediately, without a confirmation modal.
    3. **Typed Plan (%) Clamping**: When the user types the activity's `Plan (%)`, a value greater than `100.0` is set to exactly `100.0` (Aligned with the weekly Upper Clamping in AC 1.5). Because the typed value is at most `100.0`, the weekly values distributed from it (AC 3.1) never exceed `100.0`. The other input rules of [ETM-7348](https://pttep.atlassian.net/browse/ETM-7348) AC 3.1 are unchanged.
    
4. **Unsaved Changes & Save**:

    1. Editing a weekly Plan (%) cell marks the screen as having unsaved changes (`isDirty = true`), so `[ Back ]` triggers the existing `Unsaved Change` modal. (Aligned with [ETM-7348](https://pttep.atlassian.net/browse/ETM-7348) AC 1.3)
    2. Clicking `[ Save ]` persists the weekly Plan (%) values **as edited** (not re-derived from Start Date, End Date and Plan (%)). The main Timeline screen must display the saved weekly values, and the cumulative Red/Green Actual bars must compare against them. (Aligned with [ETM-7349](https://pttep.atlassian.net/browse/ETM-7349) AC 3)
    
5. **Shutdown Size Change** (Aligned with [ETM-7984](https://pttep.atlassian.net/browse/ETM-7984)):

    1. **Activities matched by Template ID**: Changing the Shutdown Size rewrites their `Start Date`, `End Date` and `Plan (%)`, so their weekly Plan (%) values are also recalculated and overwritten, including any manual weekly edits.
    2. **Activities not matched by Template ID** (custom activities added via `+ Add Activity`): their weekly Plan (%) values, including manual edits, are preserved unchanged.
