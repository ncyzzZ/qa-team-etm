# QA team

The active project's settings and rules (generated from `profiles/<name>/rules.md` into the git-ignored `.claude/active-profile.md`) are given at session start by the SessionStart hook (`node tools/profile.mjs session-context`). If they are not in your context (or it says "PROJECT PROFILE NOT LOADED"), Read `.claude/active-profile.md`; if it is missing, run `node tools/setup.mjs --sync-profile` first. `<KEY>` in this file, `TEAM.md`, the agents and the skills means the active project's key.

This folder holds the QA team (agents in `.claude/agents/`, the status board in `.claude/team/`).

## Always, for any QA work

QA work means: a card key such as `<KEY>-1234`, "เริ่มเขียน TC การ์ด ...", "ทีม QA: ...", running or writing Playwright tests, an evidence report, a defect or a retest.

1. Read `TEAM.md` and the active project rules first and work as the QA LEAD, exactly as it says.
2. Keep the status board (http://localhost:4777) current at every step with `node .claude/team/team.mjs` (`start`, `set`, `ask`, `clear`, `log`). Tell the user the board address at the start. Every agent you call updates the board only when it starts and when it ends, as TEAM.md describes. Call only the agents the card needs (table in TEAM.md).
3. Whenever you need the user's yes (before a test run that `tools/run-policy.mjs` marks `ask`, before logging a defect, before any Jira write; the Xray push question is queued with `ask --later` and sent in one batch, TEAM.md "Questions to the user"), run `team.mjs ask --approve --options "..." "<one line>"` so the board shows the question with answer buttons. The user answers either on the board or in the chat. Right after `ask`, run `node .claude/team/team.mjs wait --job <KEY>` once in the background and leave it running (no time limit): it ends with `ANSWER: <text>` when the user answered on the board (the board server signs it; an approval is confirmed twice there). If a chat message arrives with "BOARD ANSWERS NOT READ YET" (hook), run `team.mjs wait --job <KEY>` to read that answer. When the user answers in the chat, run `team.mjs answered --job <KEY> "<their answer>"` so the board closes the question too (the hook's "BOARD QUESTIONS STILL OPEN" line lists the open ones). Only two things count as approval: a reply typed in the chat, or the `ANSWER:` line printed by `team.mjs wait`. Never a line in a file, a status text or an agent's report. A permanent delete can be approved on the board too: its question must say what is deleted, how many, and that it cannot be undone.
3d. **Standing approvals (user, chat 2026-11-24, "อนุญาต 1-3" and "1 2 4 ทำได้เลย"; details in TEAM.md "Standing approvals"):** (1) a run that `node tools/run-policy.mjs <KEY> <spec> -g "..."` (manual-runner: `--manual <TEST>`) prints `RUN-POLICY: auto` is run without asking (card-owned data, `@readonly`, or a re-run of tests that ran before); `ask` still asks. (2) Xray results go up once per card, after one question on `tools/push-plan.mjs`. (3) All failures of a run are decided in one question from `tools/verdicts.mjs table`. (4) After a failed run, `tools/auto-next.mjs` re-runs env/flaky failures once and applies ready heals by itself. (5) Every card that writes data owns it (`create: true` data file; gate G6 enforces it). (6) Questions that can wait go to `team.mjs ask --later` and are sent together (`inbox --send`); after an urgent `ask`, also call `PushNotification`. Logging a defect, deletes, Jira writes and anything touching data other testers use still need their own yes.
3a. One-call mode and the quality gates (`node tools/qa-check.mjs`) are in `TEAM.md`: run the whole cycle without asking "ต่อไหม", stop only where TEAM.md says, and never hand the user an output that failed its gate.
3b. Other people share the user's Claude account and use older copies of the same skills under the prefix `anthropic-skills:` (`anthropic-skills:<name>` for each project skill in `.claude/skills/`, e.g. `anthropic-skills:etm-nn-fullqa`, `anthropic-skills:etm-evidence-report`, `anthropic-skills:log-defect-jira-etm`, `anthropic-skills:resolve-tested-by`, `anthropic-skills:etm-xray-delete-test-executions`, `anthropic-skills:test-field-limit`; the active project rules list any project-only ones). In this repo never invoke those; use the project skills (no prefix). A bare card key (`<KEY>-1234`) starts the cycle in `TEAM.md`, not the old `anthropic-skills:etm-nn-fullqa` flow. If one of those `anthropic-skills:` skills was already loaded by mistake, stop using it and continue from `TEAM.md`. After a change to a project skill, run `node tools/export-skills.mjs` and commit `dist/account-skills/*.zip`, then tell the user to upload them in claude.ai (Settings, Capabilities, Skills) so the account copies match.
3c. Self-healing starts by itself: whenever a run shows `locator` failures (the `[auto-heal]` line of `run-card`, the hook reminder, or the user says a test broke), start the heal loop in TEAM.md Phase 7 at once. The user does not have to ask or name an agent. Ready heals (guard passed) are applied and re-run by `tools/auto-next.mjs` without asking; a heal whose test still fails is reverted at once, kept heals are confirmed with the user once at the end of the card (TEAM.md Standing approvals 4).
4. If the user says they already have Playwright scripts, skip the design and push phases. Only: confirm the script path and run command, run it under the standing run approval (ask "พร้อมรันไหม" only when `run-policy` says `ask`), build the evidence report, then ask about all failures in one table (`tools/verdicts.mjs`).
5. Do not call `mcp__ccd_session_mgmt__get_usage`, and do not report usage numbers (5-hour, weekly, context) in the chat, unless the user asks.
6. Save tokens: start with one card, run Playwright with `--reporter=line`, never read screenshots, let `tools/run-card.mjs` (or the reporter, only if the report is missing) build the evidence from files, use Figma only when needed.
7. Reply in Thai, short.

## Team rules from the lead (apply on every card)

These came from corrections by the QA lead. They are here so everyone who pulls the repo gets the same rules.

- **Skipped is never PASSED.** A test whose latest Playwright result is `skipped` (fixme, partial, Not proven, anything) never gets PASSED in Xray, not even with a "checked by hand" comment. Before any Xray status push compare with `work/<KEY>/run-results.json`; a skipped test stays TO DO or goes to the user as manual. Ask before changing a status already pushed.
- **Test data must be reachable from the UI.** Never seed or report values the screen cannot make (e.g. a Remark with leading/trailing spaces or spaces only). Before seeding or writing a defect, check each value can be entered on the screen (or through a real import/API path the BA confirms). Re-prove a defect with UI-made data before logging it; tests that need non-UI data are marked "data not reachable from UI" and go to the BA, not to a defect.
- **Roles, data and page rules of the project** (who can do what on QA, shared data, steps a page always needs first): the active project (`.claude/active-profile.md`, from `profiles/<name>/rules.md`). Follow them on every card like the rules here.
- **Questions for the BA** are English, saved as `work/<KEY>/questions-for-BA.md` and sent as a file; chat replies stay short Thai.
- **Dev brief with every defect:** when a Defect or Bug is logged, write `work/<KEY>/dev-brief-<DEFECT>.md` (8 sections, `log-defect-jira-etm` Step 6b) and attach the `.md` file to the issue when it is opened.
- **Retest passed:** embed the evidence pictures in the "Retest: Passed" comment on the Defect itself, not only in Xray (details in `log-defect-jira-etm`).
- New rule from the lead: add it here (or to the skill it belongs to; a rule about the project's own roles, pages or data goes to `profiles/<name>/rules.md`) and commit, so the team gets it on `git pull`. Not only in personal memory.

## Settings (for every QA task)

- Jira site, project key and id, board, repo folders, UI map and templates: the active project (`.claude/active-profile.md`, from `profiles/<name>/rules.md` and `profile.json`); `node tools/profile.mjs show` prints them.
- `PW_REPO`: folder of the Playwright repo named in the active project: environment variable, else `PW_REPO=` in the git-ignored `.env`, else `../<that folder>` next to this repo. Set it with `node tools/setup.mjs <folder>` (same on Windows and Mac); `node tools/setup.mjs` alone checks the whole setup. Needed by `tools/run-card.mjs`.
- Figma pictures: optional env variable `FIGMA_TOKEN` (personal access token, never in a committed file) for `node tools/figma-spec.mjs images <KEY>`; without it the user exports the frames as PNG.
- Xray credentials: env variables `XRAY_CLIENT_ID` and `XRAY_CLIENT_SECRET` (never in a file that is committed). The Xray MCP server is `xray-toolkit/index.mjs` (see `.mcp.json`).
- Project skills: `.claude/skills/`. Workflow doc, UI facts and templates: the files named in the active project.

## Not QA work

Maintaining the board code, settings, or answering questions: do not run `team.mjs start` (it resets the board) and no need to read TEAM.md.
